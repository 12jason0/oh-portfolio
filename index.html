JWT 인증 구조 개선 · localStorage → httpOnly CookieJWT Auth Hardening · localStorage → httpOnly Cookie

문제Problem
JWT를 localStorage에 저장하는 구조를 사용 중이었고, XSS가 발생하면 저장된 토큰이 그대로 노출될 수 있다는 것을 확인했습니다.The JWT was being stored in localStorage, and I confirmed that an XSS hit would expose the stored token directly.
후보안Candidate options
localStorage 유지 / sessionStorage로 이동 / httpOnly Cookie 전환, 세 가지를 놓고 비교했습니다. localStorage·sessionStorage는 구현은 간단하지만 XSS가 발생하면 토큰이 그대로 노출되고, httpOnly Cookie는 클라이언트 JavaScript가 아예 접근할 수 없어 노출 경로 자체를 없앨 수 있었습니다.Compared three options: keep localStorage, move to sessionStorage, or switch to an httpOnly cookie. localStorage and sessionStorage are simpler to implement but still expose the token directly under XSS; an httpOnly cookie is unreachable from client-side JavaScript entirely, removing that exposure path altogether.
선택 이유Reason for choice
SameSite·CSRF 위험과 실제 인증 요청 흐름을 함께 검토한 뒤에도 httpOnly Cookie가 XSS 노출 범위를 가장 줄일 수 있는 선택이라고 판단해 전환하기로 결정했습니다.Even after weighing the SameSite/CSRF trade-offs against the real authenticated request flow, an httpOnly cookie still cut the XSS exposure the most, so I decided to move to it.
실제 설정Actual configuration
response.cookies.set("auth", token, {
  httpOnly: true,
  secure: process.env.NODE_ENV === "production",
  sameSite: "lax",
  path: "/",
  maxAge: 60 * 60 * 24 * 365,
});
쿠키명은 auth, SameSite=Lax, 운영 환경에서만 Secure를 적용하고 유효기간은 1년으로 설정했습니다.Cookie name is auth, SameSite=Lax, Secure only in production, with a one-year maxAge.
결과Result
클라이언트 JavaScript에서 토큰에 직접 접근하는 경로를 제거했습니다.Removed the path for client-side JavaScript to access the token directly.
